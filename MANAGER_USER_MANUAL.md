# PsychReportGen Manager User Manual

This manual is for the clinic manager (or lead clinician) who maintains templates and sets up the workflow for psychologists.

## Purpose and roles

### What PsychReportGen is for

PsychReportGen helps psychologists draft reports faster by:

- Collecting structured intake/assessment information.
- Generating section drafts using a local AI model.
- Saving reports locally and allowing export to a text file.

### Who does what

- Manager
  - Sets up and maintains report templates.
  - Standardizes section names and required fields.
  - Establishes clinic workflow and best practices.
- Psychologists
  - Create reports from templates.
  - Upload/paste test score tables.
  - Review, edit, and export final reports.

## Key concepts you should know

### Templates drive the form and the AI

The template content is used for two things:

- It defines what form fields psychologists see when creating a new report.
- It influences how the AI drafts each section (including optional `AI_use:` guidance lines).

### The app is local-first (offline)

- The app does not require internet.
- The backend and AI run locally.
- Reports are stored locally.

### AI drafts are not final clinical output

AI output must be reviewed and edited by a licensed clinician. The goal is to speed up drafting and maintain consistency, not to replace clinical judgment.

## Getting started (manager)

### First-time checklist

- Confirm the app launches successfully.
- Confirm the Templates page shows the clinic’s starting templates.
- Confirm at least one template is marked Default.
- Do one complete “test report” run:
  - Create a report using the default template.
  - Generate a few sections.
  - Export the report.

## Managing templates

Go to **Report Templates** to create, edit, and delete templates.

A template has:

- Name
- Description
- Template type (Intake / Progress / Evaluation / Discharge)
- Content / Instructions (this is the important part)
- Default flag

### Creating a new template

1. Open **Report Templates**.
2. Select **New Template**.
3. Fill in Name, Description, Type.
4. Paste or write the template Content.
5. Select **Set as default template** if you want this to appear automatically for new reports.
6. Select **Create**.

### Editing an existing template

1. Open **Report Templates**.
2. Select **Edit** on the template.
3. Update the Content.
4. Select **Update**.

### Deleting a template

1. Open **Report Templates**.
2. Select **Delete**.
3. Confirm deletion.

If psychologists already used the template for reports, deleting the template does not automatically remove existing reports.

## Template content formats (how to write templates)

The app currently supports two formats for template content:

- A text-based “legacy” format (recommended for managers because it is editable in plain text).
- A JSON format (more structured, but harder to edit without technical support).

### Recommended: legacy text format

The new report form is generated by scanning your template content for:

- Section headers
  - Examples:
    - `1. CLIENT & ADMINISTRATIVE INFORMATION`
    - `2. REASON FOR REFERRAL`
    - `3. TESTS ADMINISTERED`
- Field lines inside each section
  - A field line should include a label, a colon, and a type annotation in brackets.

Supported field types you can use in bracket annotations:

- `text`
- `textarea`
- `date`
- `date_multi`
- `dropdown:Option A, Option B, Option C`
- `multi_select:Option A, Option B`
- `checkboxes:Option A, Option B`
- `yes_no`
- `file_upload`
- `table`

Example snippet:

- `Date of Birth: [date:required]`
- `Referral source: [text]`
- `Presenting concerns: [textarea]`
- `Languages spoken at home: [text]`
- `Primary diagnoses considered: [dropdown:ADHD, ASD, Anxiety, Other]`

### How to guide AI per section using `AI_use:`

Inside your template content, you can add guidance lines starting with `AI_use:` under a section.

Guidance should:

- Be short.
- Be factual.
- Tell the AI what to do (and what not to do).

Example:

- `AI_use: Summarize referral concerns using only the parent interview notes. Do not add diagnoses.`

If you do not include `AI_use:` guidance for a section, the backend will use built-in default guidance.

## Important section naming conventions (affects UI)

Some parts of the New Report screen have special behaviors based on the section title.

### Tests Administered

If you have a section titled exactly:

- `Tests Administered`

The app will show a specialized interface where psychologists can:

- Upload score tables.
- Paste tables (from Excel/Google Sheets).
- Preview the pasted table.

Recommendation:

- Keep this section title as `Tests Administered` if you want that feature.

### Demographics and Family History

If your section title includes:

- the word `demographic` (case-insensitive)
- or the phrase `family history` (case-insensitive)

The app will ensure a free-text field for:

- `Languages at home`

Recommendation:

- If you want consistent data capture, include an explicit field for languages.

## How psychologists create a report (overview for managers)

### New Report

Psychologists typically:

1. Go to **New Report**.
2. Choose a template (default template is preselected if set).
3. Fill out the fields section-by-section.
4. For Tests Administered:
   - upload files or paste tables.
   - optionally add notes.
5. Select the generate action (the app generates section drafts).
6. Review and edit.
7. Save and later export from Reports.

Manager note:

- The better and more structured your template fields are, the better the AI drafting tends to be.

### Reports (view/export)

In **Reports**:

- Users can view previously created reports.
- Export saves a `.txt` file of the report content.

## Documents (uploads)

In **Documents**:

- Users can upload `.txt`, `.pdf`, `.doc`, `.docx`.
- Uploaded documents display extracted text when available.

Manager note:

- Document upload is useful for reference and future workflows.
- Depending on the current configuration, uploaded documents may not automatically be used during section generation.

## Best practices for a clinic manager

### Template governance

- Maintain a “clinic standard template” and set it as Default.
- Keep a version history outside the app (for example, paste template content into a dated Word/Google Doc).
- Make changes deliberately and communicate changes to psychologists.

### Make templates consistent

- Keep section titles standardized.
- Keep field labels consistent across templates.
- Use a small number of field types.

### Improve AI reliability

- Put crucial info into explicit fields instead of long free-text.
- Add `AI_use:` guidance for sections where wording must be carefully controlled.
- Keep guidance focused on:
  - what to include
  - what not to add
  - what to do if information is missing

### Rollout process

- Test new/updated templates with 1–2 sample cases before clinic-wide use.
- Have one clinician review AI drafts from the new template for:
  - completeness
  - tone
  - any hallucinations

## Troubleshooting (manager)

### The app shows a “Starting Application…” screen for a long time

Possible causes:

- A background service did not start.
- Another app is using a required port.

What to do:

1. Close the app.
2. Re-open the app.
3. If the issue persists, provide the support person with the log file:
   - `C:\Users\<user>\report-generator-backend.log`

### AI generation fails

Possible causes:

- The local AI service is not running.
- The required model is missing.

What to do:

- Close the app and re-open.
- If there is an error message about the model, share it with the support person.

### A template does not create the form fields you expected

Common reasons:

- Field lines are missing the bracket type annotation.
- The section header format does not match expected patterns.

Tips:

- Make sure fields look like: `Label: [text]` or `Label: [dropdown:Option A, Option B]`.
- Save the template and re-open **New Report** to confirm the form updates.

## Limitations to be aware of

- Export is currently plain text (`.txt`).
- The app is designed for local/offline use and does not include multi-user accounts.
- AI generation should be treated as a drafting assistant.

If you want clinic-specific enhancements (PDF/DOCX export, template locking, user roles), plan a short development cycle and test in a pilot before rolling out.
